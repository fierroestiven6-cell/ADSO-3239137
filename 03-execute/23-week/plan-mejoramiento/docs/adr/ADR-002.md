# ADR-002: Inventory Concurrency Control

**Project:** Mobility Aids  
**ADR ID:** ADR-002  
**Status:** Accepted  
**Date:** 2026-11-08

## 1. Context

Mobility Aids allows operators to register loans of technical aids.

Multiple operators may attempt to deliver the same available inventory unit simultaneously.

The system must prevent inventory inconsistencies and guarantee that an unavailable unit cannot be assigned twice.

## 2. Decision

Inventory allocation must be performed as an atomic operation within a database transaction.

The operation must verify available inventory before confirming a loan.

When multiple operators request the last available unit:

- Only one operation can succeed.
- The competing operation must fail.
- The unsuccessful operation must return HTTP 409 Conflict.
- Inventory quantities must remain consistent.

## 3. Rationale

Concurrency control is necessary to preserve inventory integrity.

An atomic transaction prevents competing operations from independently assigning the same available unit.

## 4. Consequences

### Positive consequences

- Prevents duplicate inventory allocation.
- Maintains consistent inventory quantities.
- Provides predictable conflict responses.
- Protects business rules during simultaneous operations.

### Constraints

- Inventory validation and allocation must be atomic.
- Failed transactions must not modify inventory.
- The implementation must preserve the approved API contract.

## 5. Compliance

All inventory allocation operations must follow this decision.

Automated tests must verify simultaneous requests for the last available unit.
