# ADR-002: Inventory Concurrency Control

**Project:** Mobility Aids  
**ADR ID:** ADR-002  
**Status:** Accepted  
**Date:** 2026-11-08
**Reviewed:** 2026-11-26 (decision unchanged)

------------------------------------------------------------------------------------------------------------------------

## 1. Context

Mobility Aids allows authorized managers to register loans of technical aids.

Multiple managers may attempt to deliver the same available inventory unit simultaneously.

The system must prevent inventory inconsistencies and guarantee that an available unit cannot be assigned more than once.

Inventory operations must preserve the business rules established in the project specification and the logical data model.

## 2. Decision

Inventory allocation must be performed as an atomic operation within a database transaction.

Before confirming a loan, the backend must verify that sufficient inventory is available.

The inventory update and loan registration must be committed as a single transaction.

When multiple managers request the last available unit simultaneously:

- Only one operation can succeed.
- The competing operation must fail.
- The unsuccessful operation must return HTTP `409 Conflict`.
- Inventory quantities must remain consistent.
- Failed transactions must not leave incomplete loan records or inventory modifications.

Return operations must also preserve inventory consistency and prevent duplicate inventory increases.

## 3. Rationale

Concurrency control is necessary to preserve inventory integrity.

An atomic database transaction ensures that inventory validation, allocation, and loan registration are processed consistently.

Without appropriate concurrency control, two simultaneous requests could assign the same available unit, resulting in incorrect inventory quantities.

The same consistency principle applies to returns, where a loan line must not increase available inventory more than once.

## 4. Consequences

### Positive consequences

- Prevents duplicate inventory allocation.
- Maintains consistent inventory quantities.
- Provides predictable conflict responses.
- Protects business rules during simultaneous operations.
- Prevents incomplete lending transactions.
- Supports reliable loan and return history.

### Constraints

- Inventory validation and allocation must be atomic.
- Loan registration and inventory updates must succeed or fail together.
- Failed transactions must not modify inventory.
- Available inventory must never become negative or exceed total inventory.
- Return operations must prevent duplicate inventory increases.
- The implementation must preserve the approved API contract.
- Concurrency behavior must be verified through automated tests.

## 5. Compliance

All inventory allocation and return operations must follow this decision.

Automated tests must verify simultaneous requests for the last available unit.

The expected result is:

1. One valid operation succeeds.
2. The competing operation receives HTTP `409 Conflict`.
3. Inventory remains consistent.
4. No incomplete loan operation is persisted.

Return tests must also verify that the same loan line cannot be returned more than once.
