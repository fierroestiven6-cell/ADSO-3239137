# Auditoría de API — 2026-11-26

## Alcance

Revisión estática de rutas, controladores, modelos y contrato. PHP y Composer no están disponibles en este equipo, por lo que no se ejecutó PHPUnit ni se verificó el comportamiento contra una base de datos.

## Hallazgos

### Alto — Registro público crea cuentas de manager

`POST /api/register` no requiere autenticación y `AuthController::register` asigna el rol `manager` y entrega un token. La especificación HU-02 establece que solo un administrador puede crear managers; además, CA-01.3 indica que solo login y health son públicos. Cualquier visitante puede obtener permisos operativos.

**Referencias:** `api/routes/api.php`, `api/app/Http/Controllers/AuthController.php`, `docs/spec.md` (HU-02, CA-01.3), `docs/tasks.md` (T-07, T-14).

**Recomendación:** retirar el registro público y exponer la creación de managers bajo autenticación y autorización `admin`; agregar pruebas negativas para solicitudes anónimas y usuarios `manager`.

### Alto — Los tokens no declaran vencimiento de ocho horas

El login crea tokens Sanctum sin fecha `expires_at`. La especificación CA-01.1 requiere expiración a las ocho horas. La configuración de expiración global y la revocación por inactividad no se han verificado en ejecución.

**Referencias:** `api/app/Http/Controllers/AuthController.php`, `api/config/sanctum.php`, `docs/spec.md` (CA-01.1).

**Recomendación:** asignar explícitamente el vencimiento requerido y probarlo con el reloj de pruebas.

### Medio — El informe requerido no está implementado

La API ofrece `/reports/summary`, con conteos generales. La historia HU-10 exige un informe de ayudas más solicitadas, filtrado por periodo y con categoría histórica congelada. La ruta y consulta requeridas no aparecen en el controlador.

**Referencias:** `api/routes/api.php`, `api/app/Http/Controllers/ReportController.php`, `docs/spec.md` (HU-10), `docs/tasks.md` (T-11, T-16).

### Medio — Health check difiere del contrato

Laravel registra `/up`; el contrato define `GET /health` como endpoint público. No hay alias `/health` configurado ni prueba de respuesta para `/up`.

**Referencias:** `api/bootstrap/app.php`, `docs/api-contract.md`, `docs/tasks.md` (T-01).

### Medio — La API permite borrar beneficiarios sin préstamos

`BeneficiaryController::destroy` elimina registros cuando no tienen préstamos. HU-05 indica que los beneficiarios no se pueden borrar. La regla actual permite una operación prohibida por el contrato.

**Referencias:** `api/app/Http/Controllers/BeneficiaryController.php`, `docs/spec.md` (CA-05.3).

### Medio — Respuestas de error no están normalizadas

Los controladores mezclan errores de validación, `abort(...)` y JSON con formas distintas. El contrato requiere `code`, `message` y `details` para errores. Las pruebas de contrato y la configuración de excepciones no se pudieron ejecutar en este entorno.

**Referencias:** `docs/api-contract.md` (sección 3), controladores bajo `api/app/Http/Controllers/`.
